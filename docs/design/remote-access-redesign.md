# 远程访问重设计：工作空间为中心、局域网与中转合一

> 状态：已实施（2026-10-12，#301）。B1 core（#314）、B2 web 源模型与三组侧栏（#311）、B3 远程访问页（#348）、B4 设置固定本机（#322）、B5 画布分享入口（#365）、B6 手机与 `/j/`（#312）、B7 术语与文档。线上形状见 [core 的 JSON 面](../contracts/core-json-api.md) §68，现状见[架构](../guides/architecture.md)与[客户端平台](../guides/client-platforms.md)。

## 1. 要解决的问题

此前「远程」散在几处：侧栏按源分组、设置里有「切换服务」与「服务」一组、远程访问页把局域网直连、经中转分享本机、中转账号与「我连接的其他 Armadra」列成三段。结果是：

- 「切换服务」与「加入他人」两条路并存，换当前源要手动，设置页跟着当前源跑到别人的机器上；
- 局域网与中转是两个开关、两套说法，用户分不清「对外服务」「分享本机」「远程服务」各管什么；
- 经分享链接加入的源与自己的电脑混在一起，看不出主人、权限与到期；
- 1 天的分享链接经云登录兑换后能拿到约 31 天的授予租约。

## 2. 设计

- **工作空间为中心**：侧栏三组「这台电脑 / 我的其他电脑 / 他人分享」（手机两组「我的电脑 / 他人分享」）。点哪个工作空间就打开哪个画布；当前源由打开的工作空间推导（`canvas-store.sourceId` 镜像到源表，`setCurrent` 收为内部），没有手动「切换服务」。他人的工作空间带主人名字、首字母头像与权限；画布右上写「<主人> 的 <工作空间> · <权限>」与在线成员。
- **设置恒指本机**：页头「本机 · <电脑名>」；设置页一律读写本机 core，只有「当前工作空间」页跟随打开的工作空间。ownerOnly 的页在页面的本机 core 不在眼前时（服务器壳、原生 App、中转托管页面）按那台 core 的身份会话判，访客看不到。
- **局域网与中转合一**：一个开关「允许其他设备访问这台电脑」，可达范围「仅局域网」（缺省，无需账号，就是 Gateway：`enabled` + `listen=private`）/「局域网 + 互联网」（登录中转账号，增加互联网路线）。`listen=all` 在「高级」；服务器壳托管时局域网一半只读。分享链接加入的源只有互联网一条路；「配对另一台我的电脑」补局域网路线。
- **远程访问页**：
  - A「这台电脑」：开关与可达范围、配对二维码与 8 位配对码、互联网路线上的分享链接（分享唯一的管理处）、中转账号（路线状态、启用 / 停用、改口令、登出、移除）、我的其他电脑（配对另一台、从中转账号添加）；「高级」里是监听、端口、公网来源、证书、添加中转账号与中转侧待清理。
  - B「他人分享」：别人分享给我的电脑（主人、权限、到期、退出）与「通过链接加入」。
  - 访客远程服务行（分享链接建的、保管访客刷新令牌）从账号列表隐藏。
  - 已配对设备留在相邻的「设备与会话」页（成员也要看自己的设备），不在这里重复。
- **画布分享入口**：右上工具簇的「分享」与工作空间菜单的「分享」→ 弹层：范围（此工作空间 / 仅此会话）、权限（只读缺省 / 可编辑 / 可执行；可接管只在设置）、有效期（7 天缺省 / 1 天 / 30 天）。互联网路线没开时弹层内就地开启，没有账号先登录。只给主人、只给这台电脑上的工作空间。
- **手机与浏览器**：连接页两组；不再用加入的主机替换本机；换到已挂着的连接不重载（只有「管理连接」回连接页）。`/j/` 保留一次「加入」点击，之后直达画布；访客刷新令牌按 签发方 + 链接 存 localStorage，寿命 = 链接到期，401 / `accessRevoked` 即清。
- **术语**：界面不出现 源 / 挂载 / Gateway / 隧道 / 中继节点 / relay / 签发方 / 断言 / hostId；中文说「中转账号」「互联网路线」「局域网」，英文用 Remote access / Internet route / remote access account。代码与契约里的名字不变。
- **安全**：只读由分享方 core 判定；经云登录兑换的授予租约取 `min(断言租约, 邀请到期)`；只读全量矩阵测试覆盖每条 runtime 路由与带 scope 的 procedure。
